# Floor and Ceil in a Binary Search Tree

> **Floor** = largest BST value that is less than or equal to the key.  
> **Ceil** = smallest BST value that is greater than or equal to the key.

---

## Example BST

```text
              8
            /   \
           4     12
          / \   /  \
         2   6 10   14
            /
           5
```

For `key = 7`:

```text
Floor = 6  (largest value ≤ 7)
Ceil  = 8  (smallest value ≥ 7)
```

```text
Sorted values: 2, 4, 5, 6, 8, 10, 12, 14
                            ↑
                          key = 7

floor ← 6                 8 → ceil
```

---

## Exact Match

For `key = 5`:

```text
Floor = 5
Ceil  = 5
```

If the key exists in the BST, it is both the floor and the ceil.

---

## Find Floor 💡

Floor must be `≤ key`.

### Rules

```text
current == key → exact floor found
current > key  → current is too large, move LEFT
current < key  → current is a floor candidate, save it and move RIGHT
```

### Example: Floor of `7`

```text
              8
             /
            4
             \
              6
```

```text
At 8:
7 < 8 → 8 is too large → go LEFT

At 4:
7 > 4 → 4 can be floor → save floor = 4 → go RIGHT

At 6:
7 > 6 → 6 is a closer floor → save floor = 6 → go RIGHT

Reach NULL → answer = 6
```

```text
Floor(7) = 6
```

---

## Find Ceil 💡

Ceil must be `≥ key`.

### Rules

```text
current == key → exact ceil found
current < key  → current is too small, move RIGHT
current > key  → current is a ceil candidate, save it and move LEFT
```

### Example: Ceil of `7`

```text
              8
             /
            4
             \
              6
```

```text
At 8:
7 < 8 → 8 can be ceil → save ceil = 8 → go LEFT

At 4:
7 > 4 → 4 is too small → go RIGHT

At 6:
7 > 6 → 6 is too small → go RIGHT

Reach NULL → answer = 8
```

```text
Ceil(7) = 8
```

---

## Floor vs. Ceil at a Glance

```text
             key < current?                 key > current?

Floor:       go LEFT                         save current, go RIGHT
Ceil:        save current, go LEFT           go RIGHT
```

```text
Floor looks for the closest smaller value.
Ceil looks for the closest larger value.
```

## Full Algorithm

### Floor

```text
floor = NULL
current = root

while current exists:
    if current.value == key:
        return current

    if current.value < key:
        floor = current
        current = current.right
    else:
        current = current.left

return floor
```

### Ceil

```text
ceil = NULL
current = root

while current exists:
    if current.value == key:
        return current

    if current.value > key:
        ceil = current
        current = current.left
    else:
        current = current.right

return ceil
```

## C++ Code — Complete Program

```cpp
#include <bits/stdc++.h>
using namespace std;

struct TreeNode {
    int val;
    TreeNode *left, *right;

    TreeNode(int value) : val(value), left(nullptr), right(nullptr) {}
};

class Solution {
public:
    TreeNode* findFloorNode(TreeNode* root, int key) {
        TreeNode* floorNode = nullptr;
        TreeNode* current = root;

        while (current != nullptr) {
            if (current->val == key) {
                return current;
            }

            if (current->val < key) {
                // This is a valid floor candidate. Look for a larger one.
                floorNode = current;
                current = current->right;
            } else {
                // Current value is too large for floor.
                current = current->left;
            }
        }

        return floorNode;
    }

    TreeNode* findCeilNode(TreeNode* root, int key) {
        TreeNode* ceilNode = nullptr;
        TreeNode* current = root;

        while (current != nullptr) {
            if (current->val == key) {
                return current;
            }

            if (current->val > key) {
                // This is a valid ceil candidate. Look for a smaller one.
                ceilNode = current;
                current = current->left;
            } else {
                // Current value is too small for ceil.
                current = current->right;
            }
        }

        return ceilNode;
    }
};

void deleteTree(TreeNode* root) {
    if (root == nullptr) return;
    deleteTree(root->left);
    deleteTree(root->right);
    delete root;
}

void printNode(const string& label, TreeNode* node) {
    cout << label << ": ";
    if (node) {
        cout << node->val;
    } else {
        cout << "None";
    }
    cout << endl;
}

int main() {
    /* Create this BST:
                  8
                /   \
               4     12
              / \   /  \
             2   6 10   14
                /
               5
    */
    TreeNode* root = new TreeNode(8);
    root->left = new TreeNode(4);
    root->right = new TreeNode(12);
    root->left->left = new TreeNode(2);
    root->left->right = new TreeNode(6);
    root->left->right->left = new TreeNode(5);
    root->right->left = new TreeNode(10);
    root->right->right = new TreeNode(14);

    int key = 7;
    Solution solution;

    cout << "Key: " << key << endl;
    printNode("Floor", solution.findFloorNode(root, key));
    printNode("Ceil", solution.findCeilNode(root, key));

    deleteTree(root);
    return 0;
}
```

**Output:**

```text
Key: 7
Floor: 6
Ceil: 8
```

## Why Return a Node Pointer Instead of `-1`?

A BST may contain `-1` as a real value.

```text
      0
     /
   -1
```

Returning a pointer lets us clearly show when a floor or ceil does not exist.

```text
nullptr → no answer exists
```

## Edge Cases

### Key Smaller Than Every Node

For the main BST, `key = 1`:

```text
Floor = None
Ceil  = 2
```

### Key Larger Than Every Node

For the main BST, `key = 15`:

```text
Floor = 14
Ceil  = None
```

### Key Is Present

```text
key = 5
Floor = 5
Ceil  = 5
```

### Empty Tree

```text
Floor = None
Ceil  = None
```

## Complexity

Let `H` be the height of the BST.

| Operation | Time | Extra Space |
|---|---:|---:|
| Find floor | `O(H)` | `O(1)` |
| Find ceil | `O(H)` | `O(1)` |

```text
Balanced BST → H ≈ log N → O(log N)
Skewed BST   → H = N     → O(N)
```

## Interview Questions 🎯

### 1. What is floor in a BST?

The largest value that is less than or equal to the key.

### 2. What is ceil in a BST?

The smallest value that is greater than or equal to the key.

### 3. What happens when the key exists in the tree?

The key itself is both floor and ceil.

### 4. Why save a floor candidate when `current < key`?

It is valid, but a larger valid value may exist in the right subtree.

### 5. Why save a ceil candidate when `current > key`?

It is valid, but a smaller valid value may exist in the left subtree.

### 6. What is the time complexity in a balanced BST?

`O(log N)`.

### 7. What is the worst-case time complexity?

`O(N)` for a skewed BST.

### 8. Why avoid using `-1` to represent “not found”?

`-1` can be a valid value in the BST. `nullptr` is unambiguous.
