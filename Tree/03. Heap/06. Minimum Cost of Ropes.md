# Minimum Cost of Connecting Ropes

> Given rope lengths, connect all ropes into one rope with the minimum total cost.

The cost of connecting two ropes is:

```text
cost = first rope length + second rope length
```

---

## Example 1

```text
Ropes: [4, 3, 2, 6]
```

Always connect the two smallest ropes first.

```text
Step 1: 2 + 3 = 5
Cost = 5
Ropes left: [4, 5, 6]

Step 2: 4 + 5 = 9
Cost = 9
Ropes left: [6, 9]

Step 3: 6 + 9 = 15
Cost = 15
Ropes left: [15]
```

```text
Total cost = 5 + 9 + 15 = 29
```

---

## Why Not Connect Large Ropes First?

A bad choice:

```text
Ropes: [4, 3, 2, 6]

Step 1: 4 + 6 = 10, cost = 10
Step 2: 2 + 3 = 5,  cost = 5
Step 3: 5 + 10 = 15, cost = 15

Total cost = 10 + 5 + 15 = 30
```

```text
30 > 29 ✗
```

Combining large ropes early makes that large combined rope get added again later, increasing the total cost.

---

## Greedy Rule 💡

```text
Always connect the two smallest available ropes.
```

Use a **min heap** so we can quickly get the two smallest ropes.

```text
Min heap top = smallest rope
```

---

## Why Does Greedy Work?

Every time a rope is merged, its length becomes part of future merge costs too.

```text
If a small rope is merged early:
small value is added many times → small extra cost

If a large rope is merged early:
large value is added many times → large extra cost
```

So we want short ropes to be deeper in the connection process and large ropes to be merged later.

This is the same greedy idea used in:

```text
Huffman Coding
Optimal Merge Pattern
```

---

## Connection Tree View

For:

```text
[1, 2, 3, 4, 5]
```

Optimal merges:

```text
1 + 2 = 3
3 + 3 = 6
4 + 5 = 9
6 + 9 = 15
```

Connection tree:

```text
             15
            /  \
           6    9
          / \  / \
         3   3 4   5
        / \
       1   2
```

The internal-node values are exactly the merge costs:

```text
3 + 6 + 9 + 15 = 33
```

## Example 2

```text
Ropes: [1, 2, 3, 4, 5]
```

| Step | Two smallest ropes | New rope | Total cost so far |
|---:|---|---:|---:|
| 1 | `1, 2` | `3` | `3` |
| 2 | `3, 3` | `6` | `9` |
| 3 | `4, 5` | `9` | `18` |
| 4 | `6, 9` | `15` | `33` |

```text
Minimum total cost = 33
```

---

## Algorithm

```text
1. Put all rope lengths into a min heap.
2. totalCost = 0
3. While heap has more than one rope:
      a. Remove the smallest rope.
      b. Remove the next smallest rope.
      c. combined = first + second
      d. totalCost += combined
      e. Insert combined back into heap.
4. Return totalCost.
```

## Min Heap Trace: `[4, 3, 2, 6]`

```text
Initial values: 2, 3, 4, 6
```

```text
Remove 2 and 3:
combined = 5
total = 5

Heap now contains: 4, 5, 6
```

```text
Remove 4 and 5:
combined = 9
total = 5 + 9 = 14

Heap now contains: 6, 9
```

```text
Remove 6 and 9:
combined = 15
total = 14 + 15 = 29

Heap now contains: 15
```

Only one rope remains, so stop.

## C++ Code — Complete Program

```cpp
#include <bits/stdc++.h>
using namespace std;

long long minimumCostToConnectRopes(const vector<long long>& ropes) {
    // Zero or one rope needs no connection.
    if (ropes.size() <= 1) return 0;

    // Smallest rope is always at the top.
    priority_queue<long long,
                   vector<long long>,
                   greater<long long>> minHeap(ropes.begin(), ropes.end());

    long long totalCost = 0;

    while (minHeap.size() > 1) {
        long long first = minHeap.top();
        minHeap.pop();

        long long second = minHeap.top();
        minHeap.pop();

        long long combined = first + second;
        totalCost += combined;

        // The combined rope can be used in later connections.
        minHeap.push(combined);
    }

    return totalCost;
}

int main() {
    vector<long long> ropes1 = {4, 3, 2, 6};
    vector<long long> ropes2 = {1, 2, 3, 4, 5};
    vector<long long> ropes3 = {5};
    vector<long long> ropes4 = {10, 20};

    cout << "[4, 3, 2, 6]    → "
         << minimumCostToConnectRopes(ropes1) << endl;

    cout << "[1, 2, 3, 4, 5] → "
         << minimumCostToConnectRopes(ropes2) << endl;

    cout << "[5]             → "
         << minimumCostToConnectRopes(ropes3) << endl;

    cout << "[10, 20]        → "
         << minimumCostToConnectRopes(ropes4) << endl;

    return 0;
}
```

**Output:**

```text
[4, 3, 2, 6]    → 29
[1, 2, 3, 4, 5] → 33
[5]             → 0
[10, 20]        → 30
```

## Special Cases

### No Ropes

```text
[]
```

```text
Cost = 0
```

### One Rope

```text
[5]
```

No connection is needed.

```text
Cost = 0
```

### Two Ropes

```text
[10, 20]
```

Only one connection is possible.

```text
Cost = 10 + 20 = 30
```

### Equal Ropes

```text
[5, 5, 5, 5]

5 + 5 = 10
5 + 5 = 10
10 + 10 = 20

Total = 10 + 10 + 20 = 40
```

## Complexity

| Resource | Complexity | Reason |
|---|---:|---|
| Build min heap | `O(N)` | Build from all rope values. |
| Merge operations | `O(N log N)` | `N - 1` merges; each uses heap pop/push. |
| Total time | `O(N log N)` | Heap operations dominate. |
| Extra space | `O(N)` | Min heap stores rope lengths. |

> Use `long long`, because repeated rope sums can become larger than `int`.

## Interview Questions 🎯

### 1. Which data structure is used for this problem?

A min heap / min priority queue.

### 2. Why always combine the two smallest ropes?

Small ropes may be used in several later merges. Keeping those repeated additions small gives minimum total cost.

### 3. What happens after two ropes are connected?

Their combined length becomes a new rope and is inserted back into the heap.

### 4. What is the time complexity?

`O(N log N)`.

### 5. Why is this called a greedy algorithm?

At every step, it makes the locally best choice: combine the two smallest ropes.

### 6. What is the cost for one rope?

`0`, because it is already one final rope.

### 7. Why use `long long`?

The running total and combined rope lengths can exceed the range of `int`.
