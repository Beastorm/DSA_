# Construct a Binary Tree from Inorder and Postorder Traversal

> Given inorder and postorder traversals, build the unique binary tree.

This works when all node values are **distinct**.

[Construct a Binary Tree from Inorder and Postorder Traversal](https://htmlpreview.github.io/?https://github.com/Beastorm/DSA_/blob/main/junk/pages/buildtree-post-visualizer.html)

---

## Traversal Rules 💡

```text
Inorder:   Left → Root → Right
Postorder: Left → Right → Root
```

The important difference is:

```text
Preorder:  root is at the START
Postorder: root is at the END
```

---

## Example 1

```text
inorder   = [40, 20, 50, 10, 60, 30]
postorder = [40, 50, 20, 60, 30, 10]
```

### Find the Root

The last element of postorder is always the root.

```text
postorder = [40, 50, 20, 60, 30, 10]
                                  ↑
                              root = 10
```

Find `10` in inorder:

```text
inorder = [40, 20, 50, 10, 60, 30]
                          ↑
                       root = 10
```

Split inorder around `10`:

```text
inorder = [40, 20, 50 | 10 | 60, 30]
              left subtree  root  right subtree
```

Final tree:

```text
           10
          /  \
        20    30
       /  \  /
      40  50 60
```

**Output (level order):**

```text
[10, 20, 30, 40, 50, 60]
```

## Why Store Inorder Indexes?

For every root, we must quickly find its index in the inorder array.

```text
value → index

40 → 0
20 → 1
50 → 2
10 → 3
60 → 4
30 → 5
```

The provided code uses `std::map`:

```text
find root index → O(log N)
```

Without stored indexes, scanning inorder every time can make the solution `O(N²)`.

> Replacing `map<int, int>` with `unordered_map<int, int>` gives `O(1)` average lookup and `O(N)` average total time.

---

## Recursive Idea

Keep the current ranges in both arrays:

```text
inStart, inEnd       → current inorder range
postStart, postEnd   → current postorder range
```

For each call:

```text
1. postorder[postEnd] is the root.
2. Find root's position in inorder.
3. Count left subtree nodes:
      numsLeft = inRoot - inStart
4. Use numsLeft to split the postorder range.
5. Build left and right subtrees.
```

---

## Recursive Flow

```text
build(inStart, inEnd, postStart, postEnd):

if inStart > inEnd OR postStart > postEnd:
    return NULL

root = postorder[postEnd]
inRoot = inMap[root]
numsLeft = inRoot - inStart

root.left = build(
    inStart,
    inRoot - 1,
    postStart,
    postStart + numsLeft - 1
)

root.right = build(
    inRoot + 1,
    inEnd,
    postStart + numsLeft,
    postEnd - 1
)

return root
```

## C++ Code — Complete Program

```cpp
#include <bits/stdc++.h>
using namespace std;

struct TreeNode {
    int val;
    TreeNode *left, *right;

    TreeNode(int value) : val(value), left(nullptr), right(nullptr) {}
};

class Solution {
public:
    TreeNode* buildTree(vector<int>& inorder, vector<int>& postorder) {
        if (inorder.size() != postorder.size() || inorder.empty()) {
            return nullptr;
        }

        map<int, int> inMap;
        for (int i = 0; i < inorder.size(); i++) {
            inMap[inorder[i]] = i;  // value → inorder index
        }

        return build(inorder, 0, static_cast<int>(inorder.size()) - 1,
                     postorder, 0, static_cast<int>(postorder.size()) - 1,
                     inMap);
    }

private:
    TreeNode* build(vector<int>& inorder, int inStart, int inEnd,
                    vector<int>& postorder, int postStart, int postEnd,
                    map<int, int>& inMap) {
        if (inStart > inEnd || postStart > postEnd) return nullptr;

        // Postorder gives the root at the end of the current range.
        TreeNode* root = new TreeNode(postorder[postEnd]);

        int inRoot = inMap[root->val];
        int numsLeft = inRoot - inStart;

        root->left = build(inorder, inStart, inRoot - 1,
                           postorder, postStart, postStart + numsLeft - 1,
                           inMap);

        root->right = build(inorder, inRoot + 1, inEnd,
                            postorder, postStart + numsLeft, postEnd - 1,
                            inMap);

        return root;
    }
};

void printLevelOrder(TreeNode* root) {
    if (root == nullptr) {
        cout << "[]\n";
        return;
    }

    vector<string> values;
    queue<TreeNode*> q;
    q.push(root);

    while (!q.empty()) {
        TreeNode* current = q.front();
        q.pop();

        if (current == nullptr) {
            values.push_back("null");
            continue;
        }

        values.push_back(to_string(current->val));
        q.push(current->left);
        q.push(current->right);
    }

    while (!values.empty() && values.back() == "null") {
        values.pop_back();
    }

    cout << "[";
    for (int i = 0; i < values.size(); i++) {
        cout << values[i];
        if (i + 1 < values.size()) cout << ", ";
    }
    cout << "]\n";
}

void deleteTree(TreeNode* root) {
    if (root == nullptr) return;
    deleteTree(root->left);
    deleteTree(root->right);
    delete root;
}

int main() {
    vector<int> inorder = {40, 20, 50, 10, 60, 30};
    vector<int> postorder = {40, 50, 20, 60, 30, 10};

    Solution solution;
    TreeNode* root = solution.buildTree(inorder, postorder);

    cout << "Constructed tree (level order): ";
    printLevelOrder(root);

    deleteTree(root);
    return 0;
}
```

**Output:**

```text
Constructed tree (level order): [10, 20, 30, 40, 50, 60]
```

## Complexity

| Resource | Complexity | Reason |
|---|---:|---|
| Time | `O(N log N)` | Each node is built once; `std::map` lookup costs `O(log N)`. |
| Extra space | `O(N)` | Inorder map plus recursion stack. |

```text
Balanced tree → recursion stack O(log N)
Skewed tree   → recursion stack O(N)
```

> With `unordered_map`, lookup is `O(1)` on average, so total average time becomes `O(N)`.

## Interview Questions 🎯

### 1. Why is the root at the end of postorder?

Postorder visits nodes in this order:

```text
Left → Right → Root
```

So the last value of every current postorder range is the root.

### 2. Why is inorder needed?

Inorder shows where the root splits left and right subtrees.

```text
[left subtree | root | right subtree]
```

### 3. How is this different from preorder + inorder construction?

```text
Preorder  → root is first element
Postorder → root is last element
```

### 4. Why do we calculate `numsLeft`?

It tells us exactly how many values belong to the left subtree in postorder.

### 5. Do we need to build right before left?

Not with the range-based code above, because both postorder ranges are known. If using one pointer that moves backward through postorder, then build the right subtree first.

### 6. Can duplicate values be used?

Not for unique construction. Duplicate values make the root position in inorder ambiguous.

### 7. What is the time complexity of the provided `std::map` code?

`O(N log N)`. Using `unordered_map` makes it `O(N)` on average.

### 8. What is the space complexity?

`O(N)` for the map and recursion stack in the worst case.
