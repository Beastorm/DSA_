# Construct a Binary Tree from Preorder and Inorder Traversal

> Given preorder and inorder traversals, build the unique binary tree.

This works when all node values are **distinct**.

---

## Traversal Rules 💡

```text
Preorder: Root → Left → Right
Inorder:  Left → Root → Right
```

This gives us everything we need:

```text
Preorder tells us: the next root node
Inorder tells us: where left and right subtrees split
```

---

## Example 1

```text
preorder = [3, 9, 20, 15, 7]
inorder  = [9, 3, 15, 20, 7]
```

### Find the Root

The first preorder value is always the root.

```text
preorder = [3, 9, 20, 15, 7]
            ↑
          root = 3
```

Find `3` in inorder:

```text
inorder = [9, 3, 15, 20, 7]
              ↑
           root = 3
```

Everything left of `3` belongs to the left subtree. Everything right belongs to the right subtree.

```text
inorder = [ 9 | 3 | 15, 20, 7 ]
             left   root   right
```

So the tree starts like this:

```text
      3
     / \
    9   ?
```

The next preorder value after `9` is `20`, so it is the right subtree root.

```text
         3
        / \
       9   20
          /  \
         15   7
```

**Output:**

```text
[3, 9, 20, null, null, 15, 7]
```

            └─┘ ↑ └───────┘
            left   right

```text
Root = 3

Left inorder part:  [9]
Right inorder part: [15, 20, 7]
```

Then recursively repeat the same idea for both parts.

## Why Use a Hash Map?

At every recursive call, we must find the root in the inorder array.

```text
value → index in inorder

9  → 0
3  → 1
15 → 2
20 → 3
7  → 4
```

With a hash map:

```text
find index of root → O(1) average time
```

Without a hash map, searching the inorder array repeatedly can make the solution `O(N²)`.

---

## Simple Recursive Idea

Keep one pointer `preIndex` for the preorder array.

```text
preIndex starts at 0
```

For each recursive call:

```text
1. preorder[preIndex] is the current root.
2. Increase preIndex.
3. Find the root index in inorder.
4. Build left subtree using inorder's left part.
5. Build right subtree using inorder's right part.
```

Because preorder is `Root → Left → Right`, we must build the left subtree before the right subtree.

---

## Recursive Flow

```text
build(inStart, inEnd):

if inStart > inEnd:
    return NULL

rootValue = preorder[preIndex]
preIndex++

inRoot = position of rootValue in inorder

root.left  = build(inStart, inRoot - 1)
root.right = build(inRoot + 1, inEnd)

return root
```

---

## Step-by-Step Trace

```text
preorder = [3, 9, 20, 15, 7]
inorder  = [9, 3, 15, 20, 7]
```

### Call 1: Build the Full Tree

```text
build(0, 4)

preIndex = 0
root = preorder[0] = 3
inRoot = 1
```

```text
left subtree:  build(0, 0)    → inorder [9]
right subtree: build(2, 4)    → inorder [15, 20, 7]
```

---

### Call 2: Build the Left Subtree

```text
build(0, 0)

preIndex = 1
root = preorder[1] = 9
inRoot = 0
```

There is nothing to the left or right of `9` in this inorder range.

```text
9 is a leaf node
```

---

### Call 3: Build the Right Subtree

```text
build(2, 4)

preIndex = 2
root = preorder[2] = 20
inRoot = 3
```

```text
left subtree:  build(2, 2) → root = 15
right subtree: build(4, 4) → root = 7
```

Final tree:

```text
         3
        / \
       9   20
          /  \
         15   7
```

## C++ Code — Complete Program

```cpp
#include <bits/stdc++.h>
using namespace std;

struct TreeNode {
    int val;
    TreeNode *left, *right;

    TreeNode(int value) : val(value), left(nullptr), right(nullptr) {}
};

class Solution {
    int preIndex;
    unordered_map<int, int> inorderIndex;

    TreeNode* build(const vector<int>& preorder, int inStart, int inEnd) {
        // No values in this inorder range means no subtree.
        if (inStart > inEnd) return nullptr;

        // Preorder gives the root first.
        int rootValue = preorder[preIndex++];
        TreeNode* root = new TreeNode(rootValue);

        // Inorder splits left and right subtrees.
        int inRoot = inorderIndex[rootValue];

        // Build left first because preorder is Root → Left → Right.
        root->left = build(preorder, inStart, inRoot - 1);
        root->right = build(preorder, inRoot + 1, inEnd);

        return root;
    }

public:
    TreeNode* buildTree(const vector<int>& preorder, const vector<int>& inorder) {
        if (preorder.empty()) return nullptr;

        preIndex = 0;
        inorderIndex.clear();

        for (int i = 0; i < inorder.size(); i++) {
            inorderIndex[inorder[i]] = i;
        }

        return build(preorder, 0, static_cast<int>(inorder.size()) - 1);
    }
};

void printLevelOrder(TreeNode* root) {
    if (root == nullptr) {
        cout << "[]\n";
        return;
    }

    vector<string> values;
    queue<TreeNode*> q;
    q.push(root);

    while (!q.empty()) {
        TreeNode* current = q.front();
        q.pop();

        if (current == nullptr) {
            values.push_back("null");
            continue;
        }

        values.push_back(to_string(current->val));
        q.push(current->left);
        q.push(current->right);
    }

    // Remove unnecessary trailing null values.
    while (!values.empty() && values.back() == "null") {
        values.pop_back();
    }

    cout << "[";
    for (int i = 0; i < values.size(); i++) {
        cout << values[i];
        if (i + 1 < values.size()) cout << ", ";
    }
    cout << "]\n";
}

void deleteTree(TreeNode* root) {
    if (root == nullptr) return;
    deleteTree(root->left);
    deleteTree(root->right);
    delete root;
}

int main() {
    vector<int> preorder = {3, 9, 20, 15, 7};
    vector<int> inorder = {9, 3, 15, 20, 7};

    Solution solution;
    TreeNode* root = solution.buildTree(preorder, inorder);

    cout << "Constructed tree (level order): ";
    printLevelOrder(root);

    deleteTree(root);
    return 0;
}
```

**Output:**

```text
Constructed tree (level order): [3, 9, 20, null, null, 15, 7]
```

## Complexity

| Resource | Complexity | Reason |
|---|---:|---|
| Time | `O(N)` | Each value builds one node; hash-map lookup is `O(1)` average. |
| Extra space | `O(N)` | Inorder hash map plus recursion stack. |

```text
Balanced tree → recursion stack O(log N)
Skewed tree   → recursion stack O(N)
```

> Without the hash map, each recursive call may scan inorder to find the root. That makes the worst-case time complexity `O(N²)`.

## Interview Questions 🎯

### 1. Why is preorder useful here?

The first unprocessed preorder value is always the root of the current subtree.

### 2. Why is inorder useful here?

It splits nodes into left and right subtrees around the root.

```text
[left subtree | root | right subtree]
```

### 3. Why do we build the left subtree before the right subtree?

Preorder order is:

```text
Root → Left → Right
```

After consuming a root, the next preorder values belong to the left subtree first.

### 4. Why use a hash map?

To find each root’s inorder index in `O(1)` average time.

### 5. Are preorder and inorder always enough to build a unique tree?

Only when node values are distinct. With duplicate values, the root position in inorder can be ambiguous.

### 6. Can preorder and postorder always build a unique binary tree?

No. Different trees can have the same preorder and postorder traversals.

### 7. What is the time complexity with a hash map?

`O(N)`.

### 8. What is the space complexity?

`O(N)` for the index map and recursion stack in the worst case.
