# Minimum Time to Burn a Binary Tree from a Target Node

> If fire starts at a target node, find how many seconds it takes to burn the whole tree.

In one second, fire spreads from a node to all connected nodes:

```text
left child
right child
parent
```

## Main Problem 💡

A binary-tree node knows only its children.

```text
      parent
      /    \
   child  child
```

But fire must also move **upward** to the parent.

For example, when fire starts at node `4`:

```text
4 → 3 → 1 → 2 → 5
```

So we first create parent links.

---

## Treat the Tree Like an Undirected Graph

### Original Tree

```text
           1
          / \
         2   3
        /   / \
       4   5   6
        \
         7
```

### Parent Map

```text
child → parent

2 → 1       3 → 1
4 → 2       5 → 3       6 → 3
7 → 4
```

Now every node can move in all directions:

```text
Node 4 can move to: 7 and 2
Node 2 can move to: 4 and 1
Node 1 can move to: 2 and 3
```

```text
             1
            ↙ ↘
           2   3
           ↙   ↙ ↘
          4   5   6
          ↘
           7
```

---

## Why BFS Gives the Minimum Time

BFS processes nodes by distance from the target.

```text
BFS level 0 = burns at time 0
BFS level 1 = burns at time 1
BFS level 2 = burns at time 2
...
```

The last BFS level is the farthest node from the target. Its level number is the total burn time.


```text

Burned:  {1, 2, 3, 4, 5, 6}
```

```text
From 4 → add 7
From 5 and 6 → no new nodes
```

### Time 3

```text
Queue:   [7]
Burned:  {1, 2, 3, 4, 5, 6, 7}
```

No new nodes remain.

```text
Answer = 3 seconds
```

## Why Do We Need a `visited` Set?

Once parent links are available, there are cycles.

```text
1 → 2 → 1 → 2 → ...
```

The visited set ensures a burned node is never added again.

```text
When 2 burns:
parent 1 is already burned → do not add it again
```

---

## Full Algorithm

```text
1. Build a parent map using BFS and find the target node.
2. Put the target node in a queue and mark it visited.
3. Repeat level by level:
      a. Process all currently burning nodes.
      b. Add unburned left child, right child, and parent.
      c. Move to the next second.
4. Return the number of completed BFS levels after time 0.
```

## C++ Code — Complete Program

```cpp
#include <bits/stdc++.h>
using namespace std;

struct TreeNode {
    int val;
    TreeNode *left, *right;

    TreeNode(int value) : val(value), left(nullptr), right(nullptr) {}
};

class Solution {
    TreeNode* buildParentMap(TreeNode* root, int targetValue,
                             unordered_map<TreeNode*, TreeNode*>& parent) {
        queue<TreeNode*> q;
        q.push(root);
        TreeNode* target = nullptr;

        while (!q.empty()) {
            TreeNode* current = q.front();
            q.pop();

            if (current->val == targetValue) {
                target = current;
            }

            if (current->left) {
                parent[current->left] = current;
                q.push(current->left);
            }

            if (current->right) {
                parent[current->right] = current;
                q.push(current->right);
            }
        }

        return target;
    }

public:
    int minTimeToBurn(TreeNode* root, int targetValue) {
        if (root == nullptr) return 0;

        // Step 1: Find target and create child → parent links.
        unordered_map<TreeNode*, TreeNode*> parent;
        TreeNode* target = buildParentMap(root, targetValue, parent);

        // Target is assumed to exist. Return -1 if it does not.
        if (target == nullptr) return -1;

        // Step 2: BFS from the burning target node.
        queue<TreeNode*> q;
        unordered_set<TreeNode*> burned;

        q.push(target);
        burned.insert(target);
        int seconds = -1;

        while (!q.empty()) {
            int levelSize = q.size();
            seconds++;

            for (int i = 0; i < levelSize; i++) {
                TreeNode* current = q.front();
                q.pop();

                // Fire can spread to left child, right child, and parent.
                vector<TreeNode*> neighbours = {
                    current->left,
                    current->right,
                    parent.count(current) ? parent[current] : nullptr
                };

                for (TreeNode* next : neighbours) {
                    if (next != nullptr && !burned.count(next)) {
                        burned.insert(next);
                        q.push(next);
                    }
                }
            }
        }

        return seconds;
    }
};

void deleteTree(TreeNode* root) {
    if (root == nullptr) return;
    deleteTree(root->left);
    deleteTree(root->right);
    delete root;
}

int main() {
    /* Create this tree:
               1
              / \
             2   3
            /   / \
           4   5   6
            \
             7
    */
    TreeNode* root = new TreeNode(1);
    root->left = new TreeNode(2);
    root->right = new TreeNode(3);
    root->left->left = new TreeNode(4);
    root->right->left = new TreeNode(5);
    root->right->right = new TreeNode(6);
    root->left->left->right = new TreeNode(7);

    int target = 1;
    Solution solution;

    cout << "Minimum time to burn from node " << target << ": "
         << solution.minTimeToBurn(root, target) << " seconds" << endl;

    deleteTree(root);
    return 0;
}
```

**Output:**

```text
Minimum time to burn from node 1: 3 seconds
```

### Single Node Tree

### Target Is a Leaf

```text

      / \

```

```text

Time 1: 1

Answer = 2 seconds
```

### Skewed Tree

```text
1 → 2 → 3 → 4 → 5

Target = 3
```

```text
Time 0: 3
Time 1: 2, 4
Time 2: 1, 5

Answer = 2 seconds
```

## Complexity

| Resource | Complexity | Reason |
|---|---:|---|
| Time | `O(N)` | One BFS builds parents; one BFS burns every node once. |
| Space | `O(N)` | Parent map, burned set, and queue can store all nodes. |

- `N` = number of nodes in the tree.

## Interview Questions 🎯

### 1. Why do we need parent links?

Fire can move upward, but tree nodes normally store only child pointers.

### 2. Why is BFS used instead of DFS?

All adjacent nodes burn at the same time. BFS naturally processes one second (one distance level) at a time.

### 3. Why is a visited set needed?

It prevents revisiting already burned nodes through parent-child links.

```text
1 → 2 → 1 → ...
```

### 4. Why does BFS level equal time in seconds?

Every edge takes exactly one second for fire to cross.

```text
0 edges away → time 0
1 edge away  → time 1
2 edges away → time 2
```

### 5. What happens when the target is the root?

The root has no parent. Fire spreads only downward.

### 6. What happens for a single node?

The entire tree is already burning at time `0`.

### 7. What is the time complexity?

`O(N)`.

### 8. Can we solve this without explicitly storing all parent links?

Yes, with a recursive solution that finds the target and calculates opposite-subtree distances. The parent-map + BFS approach is easier to understand.
