# Bottom View of a Binary Tree

> Return the nodes visible when the binary tree is viewed from **below**.

For every vertical column, only the **lowest node** is visible.

---

## Main Idea: Vertical Columns 💡

Give every node a column number.

```text
root        → column 0
left child  → column - 1
right child → column + 1
```

For the bottom view, we keep updating a column. The node seen **last** in that column becomes visible from below.

---

## Example 1

```text
                         1 (0)
                       /       \
                  2 (-1)       3 (+1)
                  /    \       /    \
             4 (-2)  10 (0)  9 (0)  11 (+2)
                \
                5 (-1)
                   \
                   6 (0)
```

### What is visible from the bottom?

```text
Column -2: 4                  → visible
Column -1: 5 is below 2       → 5 is visible
Column  0: 6 is below 1,10,9  → 6 is visible
Column +1: 3                  → visible
Column +2: 11                 → visible
```

```text
Bottom view: [4, 5, 6, 3, 11]
```

### Bottom-view diagram

```text
Hidden nodes above:       2      1      3
                           \   10, 9

Visible from below:  4     5      6      3      11
                     |     |      |      |       |
Columns:            -2    -1      0     +1      +2
```

**Output:**

```text
[4, 5, 6, 3, 11]
```

## Why Do We Use BFS? 📚

BFS visits the tree from top to bottom.

```text
Level 0:  1
Level 1:  2, 3
Level 2:  4, 10, 9, 11
Level 3:  5
Level 4:  6
```

When a later node belongs to the same column, it is lower (or at the same level but later in BFS order). So we overwrite the old value.

```text
Column 0 receives nodes in this order:
1 → 10 → 9 → 6

Keep replacing the stored value:
1 → 10 → 9 → 6

Final visible value at column 0 = 6
```

---

## BFS Walkthrough

The queue stores:

```text
(node, column)
```

The map stores:

```text
column → latest / lowest node value
```

### Start

```text
Queue: [(1, 0)]
Map:   {}
```

### Process node 1

```text
Take: (1, 0)
Store: column 0 → 1
Push: (2, -1), (3, +1)

Map: { 0: 1 }
```

### Process node 2 and node 3

```text
Take: (2, -1) → column -1 becomes 2
Take: (3, +1) → column +1 becomes 3

Map: { -1: 2, 0: 1, +1: 3 }
```

### Process lower nodes

```text
Take: (10, 0) → replace column 0: 1  becomes 10
Take: (9, 0)  → replace column 0: 10 becomes 9
Take: (5, -1) → replace column -1: 2 becomes 5
Take: (6, 0)  → replace column 0: 9  becomes 6
```

Final map:

```text
-2 → 4
-1 → 5
 0 → 6
+1 → 3
+2 → 11
```

Read from left to right:

```text
[4, 5, 6, 3, 11]
```

---

## Full Algorithm

```text
1. If the tree is empty, return an empty list.
2. Put (root, 0) into a queue.
3. While the queue is not empty:
      a. Remove (node, column).
      b. Store node's value at that column, replacing the old value.
      c. Push the left child with column - 1.
      d. Push the right child with column + 1.
4. Read the map from smallest column to largest column.
5. Return the stored values.
```

## C++ Code — Complete Program

```cpp
#include <bits/stdc++.h>
using namespace std;

struct Node {
    int data;
    Node *left, *right;

    Node(int value) : data(value), left(nullptr), right(nullptr) {}
};

class Solution {
public:
    vector<int> bottomView(Node* root) {
        vector<int> answer;
        if (root == nullptr) return answer;

        // column number -> latest (bottommost) value in that column
        map<int, int> bottomNode;

        // Queue stores: node and its column number.
        queue<pair<Node*, int>> q;
        q.push({root, 0});

        while (!q.empty()) {
            Node* current = q.front().first;
            int column = q.front().second;
            q.pop();

            // Overwrite the old value in this column.
            bottomNode[column] = current->data;

            if (current->left) {
                q.push({current->left, column - 1});
            }

            if (current->right) {
                q.push({current->right, column + 1});
            }
        }

        // map keys are sorted: leftmost column to rightmost column.
        for (auto& entry : bottomNode) {
            answer.push_back(entry.second);
        }

        return answer;
    }
};

void printVector(const vector<int>& values) {
    cout << "[";
    for (int i = 0; i < values.size(); i++) {
        cout << values[i];
        if (i + 1 < values.size()) cout << ", ";
    }
    cout << "]\n";
}

void deleteTree(Node* root) {
    if (root == nullptr) return;
    deleteTree(root->left);
    deleteTree(root->right);
    delete root;
}

int main() {
    /* Create this tree:
                             1
                           /   \
                          2     3
                         / \   / \
                        4  10 9  11
                         \
                          5
                           \
                            6
    */
    Node* root = new Node(1);
    root->left = new Node(2);
    root->right = new Node(3);
    root->left->left = new Node(4);
    root->left->right = new Node(10);
    root->right->left = new Node(9);
    root->right->right = new Node(11);
    root->left->left->right = new Node(5);
    root->left->left->right->right = new Node(6);

    Solution solution;
    cout << "Bottom view: ";
    printVector(solution.bottomView(root));

    deleteTree(root);
    return 0;
}
```

**Output:**

```text
Bottom view: [4, 5, 6, 3, 11]
```

## Special Cases

### Empty Tree

```text
root = NULL
Bottom view = []
```

### Single Node Tree

```text
  1
```

```text
Bottom view = [1]
```

### Left-Skewed Tree

```text
    1
   /
  2
 /
3
```

Every node has a different column:

```text
Bottom view = [3, 2, 1]
```

## Complexity

| Resource | Complexity | Reason |
|---|---:|---|
| Time | `O(N log N)` | Each ordered-map update can take `O(log N)`. |
| Space | `O(N)` | The queue and map can store up to `N` nodes. |

- `N` = number of nodes in the tree.

> If an `unordered_map` is used with minimum/maximum column tracking, average time can be close to `O(N)`. The ordered `map` solution is simpler because it keeps columns sorted automatically.

## Interview Questions 🎯

### 1. Why does BFS help find the bottom view?

BFS processes lower levels after higher levels.

```text
Later node in a column = lower visible node
```

So we overwrite the value for that column.

### 2. Why do we overwrite instead of keeping the first value?

```text
Top view:    keep first node in a column
Bottom view: keep last node in a column
```

### 3. What does the map store?

```text
column number → current bottommost node value
```

### 4. Why use a map?

The map returns columns from left to right.

```text
-2, -1, 0, +1, +2
```

### 5. What happens when nodes share a column and a level?

With this BFS approach, the node processed later replaces the earlier one. Because left children are added first, a later right-side node wins a same-level tie.

### 6. What is the difference between top view and bottom view?

```text
Top view:    first / highest node in each column
Bottom view: last / lowest node in each column
```

### 7. What is the time complexity?

`O(N log N)` with an ordered `map`.
