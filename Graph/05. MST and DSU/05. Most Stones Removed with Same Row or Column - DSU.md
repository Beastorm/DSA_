# Most Stones Removed with Same Row or Column - DSU

> Given stones placed at coordinate points, remove a stone if another remaining stone exists in the same row or column. Return the maximum number of stones that can be removed.

## 1. Problem Statement

There are `N` stones placed at coordinate points on a 2D plane. No two stones occupy the same coordinate.

A stone can be removed when another stone still exists in the same:

```text
row OR column
```

Given:

```text
stones[i] = [row, column]
```

return the maximum possible number of stones that can be removed.

---

## Examples

### Example 1

```text
Input:
stones = [[0,0], [0,1], [1,0], [1,2], [2,1], [2,2]]
```

```text
Grid:

    0 1 2
0   S S .
1   S . S
2   . S S
```

All six stones belong to one connected group through shared rows and columns.

```text
Number of stones = 6
Number of groups = 1

Maximum removable = 6 - 1 = 5
```

```text
Output = 5
```

One stone must remain in the group because the last stone has no remaining neighbor.

## Key Insight

### Observation 1: Stones Form Connected Groups

Two stones are directly connected when they share a row or column.

Connections can also be transitive.

```text
[0,0] shares a row with [0,1]
[0,1] shares a column with [2,1]
```

Even though `[0,0]` and `[2,1]` do not directly share a row or column, all three belong to the same connected group.

---

### Observation 2: A Group of K Stones Contributes K - 1 Removals

From a connected group of `K` stones:

```text
K - 1 stones can be removed
1 stone must remain
```

Therefore, if the total number of stones is `N` and the number of connected groups is `G`:

```text
Maximum removable = N - G
```

The entire problem becomes:

```text
Count the number of connected groups.
```

---

### Observation 3: Use Rows and Columns as DSU Nodes

Instead of connecting every pair of stones directly, represent each row and column as a DSU node.

For a stone at `[row, column]`:

```text
union(row, column + offset)
```

A stone connects its row-node to its column-node.

Then:

```text
Stones sharing a row → share the same row-node
Stones sharing a column → share the same column-node
```

This automatically captures direct and chain connections.

---

### Why Is an Offset Required?

Row numbers and column numbers can be equal.

Without an offset:

```text
Stone [0,0]
union(0, 0)
```

The DSU cannot tell whether node `0` represents row `0` or column `0`.

Use:

```text
row node    = row
column node = column + maxRow + 1
```

For `maxRow = 2`:

```text
Rows:    0, 1, 2
Columns: 3, 4, 5
```

Rows and columns now occupy separate DSU ID ranges.

---

## Intuition

Imagine every row and every column has a separate team badge.

```text
Rows:    R0, R1, R2
Columns: C0, C1, C2
```

A stone at `[0,1]` joins the teams:

```text
R0 ─── C1
```

Two stones in the same row share the same row team:

```text
[0,0] → R0 ← [0,1]
```

Two stones in the same column share the same column team:

```text
[0,1] → C1 ← [2,1]
```

A chain also works:

```text
[0,0] → R0 ← [0,1] → C1 ← [2,1]
```

All three stones belong to one DSU component.

At the end:

```text
number of removable stones
= total stones - number of DSU components
```

## Algorithm

```text
1. Find the maximum row and maximum column used by the stones.

2. Create a DSU large enough for:
      all row nodes
      all offset column nodes

3. For every stone [row, column]:
      a. Convert the column to column + offset.
      b. Union the row node and column node.
      c. Store both node IDs as active nodes.

4. Count unique DSU roots among active nodes.

5. Return:
      number of stones - number of connected components
```

The screenshot implementation uses an `unordered_map` to record only the row and column nodes that actually occur in the input.

---

## What Does `stoneNodes` Store?

This part is important:

```cpp
unordered_map<int, int> stoneNodes;
```

`stoneNodes` does **not** store the original stones. It stores the IDs of the DSU nodes that are actually used by at least one stone.

For a stone `[row, column]`, the DSU contains two nodes:

```text
nodeRow = row
nodeCol = column + offset
```

So we record both IDs:

```cpp
// The key is an active DSU node ID.
// The value 1 is only a dummy marker; we do not use it.
stoneNodes[nodeRow] = 1;
stoneNodes[nodeCol] = 1;
```

### Why Is a Map Being Used Like This?

Only the keys matter. Assigning `1` means:

```text
"This DSU node exists in at least one stone."
```

If the same node appears again, the key is not duplicated:

```cpp
stoneNodes[0] = 1;  // inserts node 0
stoneNodes[0] = 1;  // still only one node 0
```

Therefore, this `unordered_map<int, int>` is effectively being used as an `unordered_set<int>` while matching the screenshot's code.

### Small Example

Suppose `offset = 3` and the stones are:

```text
[0,0], [0,1], [1,0]
```

The DSU unions are:

```text
[0,0] → union(0, 3)
[0,1] → union(0, 4)
[1,0] → union(1, 3)
```

The active DSU nodes are:

```text
row 0       → 0
row 1       → 1
column 0    → 3
column 1    → 4
```

So the map contains keys equivalent to:

```text
{0, 1, 3, 4}
```

Unused nodes are not stored because they do not belong to any stone.

### Counting the Components

After all unions, inspect only the active nodes:

```cpp
int components = 0;

for (auto it : stoneNodes) {
    int node = it.first;

    if (ds.findUPar(node) == node) {
        components++;
    }
}
```

`it.first` is the DSU node ID. `it.second` is the unused value `1`.

A node is a component root when:

```cpp
ds.findUPar(node) == node
```

Each connected group has exactly one root, so `components` becomes the number of connected stone groups.

The final answer is:

```text
maximum removable stones = total stones - components
```

> A clearer alternative would be `unordered_set<int> stoneNodes`, but the map form above is kept to follow the screenshot.

## Code

```cpp
#include <bits/stdc++.h>
using namespace std;

class DisjointSet {
private:
    vector<int> parent, rank, size;

public:
    DisjointSet(int n) {
        parent.resize(n);
        rank.resize(n, 0);
        size.resize(n, 1);

        for (int i = 0; i < n; i++) {
            parent[i] = i;
        }
    }

    int findUPar(int node) {
        if (parent[node] == node) {
            return node;
        }

        // Path compression.
        return parent[node] = findUPar(parent[node]);
    }

    void unionByRank(int u, int v) {
        int ultimateU = findUPar(u);
        int ultimateV = findUPar(v);

        if (ultimateU == ultimateV) {
            return;
        }

        if (rank[ultimateU] < rank[ultimateV]) {
            parent[ultimateU] = ultimateV;
        }
        else if (rank[ultimateU] > rank[ultimateV]) {
            parent[ultimateV] = ultimateU;
        }
        else {
            parent[ultimateV] = ultimateU;
            rank[ultimateU]++;
        }
    }

    void unionBySize(int u, int v) {
        int ultimateU = findUPar(u);
        int ultimateV = findUPar(v);

        if (ultimateU == ultimateV) {
            return;
        }

        if (size[ultimateU] < size[ultimateV]) {
            swap(ultimateU, ultimateV);
        }

        parent[ultimateV] = ultimateU;
        size[ultimateU] += size[ultimateV];
    }
};

class Solution {
public:
    int maxRemove(vector<vector<int>>& stones, int n) {
        int maxRow = 0;
        int maxCol = 0;

        for (auto it : stones) {
            maxRow = max(maxRow, it[0]);
            maxCol = max(maxCol, it[1]);
        }

        // Row IDs are 0..maxRow.
        // Column IDs begin at maxRow + 1.
        int offset = maxRow + 1;

        // The largest node ID is maxCol + offset.
        // The constructor argument is a count, so +2 is required.
        DisjointSet ds(maxRow + maxCol + 2);

        // Used like a set: keys are active DSU node IDs.
        // The value 1 is only a dummy marker.
        unordered_map<int, int> stoneNodes;

        for (auto it : stones) {
            int nodeRow = it[0];
            int nodeCol = it[1] + offset;

            ds.unionBySize(nodeRow, nodeCol);

            // Record both DSU nodes touched by this stone.
            // Repeated keys are stored only once.
            stoneNodes[nodeRow] = 1;
            stoneNodes[nodeCol] = 1;
        }

        int cnt = 0;

        for (auto it : stoneNodes) {
            if (ds.findUPar(it.first) == it.first) {
                cnt++;
            }
        }

        return n - cnt;
    }
};

int main() {
    vector<vector<int>> stones1 = {
        {0, 0}, {0, 1}, {1, 0},
        {1, 2}, {2, 1}, {2, 2}
    };

    vector<vector<int>> stones2 = {
        {0, 0}, {0, 2}, {1, 3},
        {3, 1}, {3, 2}, {4, 3}
    };

    Solution solution;

    cout << "Example 1: "
         << solution.maxRemove(stones1, stones1.size()) << endl;

    cout << "Example 2: "
         << solution.maxRemove(stones2, stones2.size()) << endl;

    return 0;
}
```

**Output:**

```text
Example 1: 5
Example 2: 4
```

### Negative Coordinates

The vector-based implementation assumes non-negative coordinates because coordinates are used as array indexes.

For negative or extremely large sparse coordinates, use coordinate compression or a map-based DSU instead.

## Common Mistakes

### Mistake 1: No Column Offset

```cpp
union(row, col); // Incorrect when row and column IDs overlap
```

Correct:

```cpp
union(row, col + maxRow + 1);
```

---

### Mistake 2: DSU Too Small

The maximum column node is:

```text
maxCol + offset
= maxCol + maxRow + 1
```

Therefore, the DSU size must be at least:

```text
maxRow + maxCol + 2
```

---

### Mistake 3: Counting Unused DSU Nodes

Do not count every DSU root. Many row and column IDs may not occur in any stone.

Count only roots among the nodes recorded in `stoneNodes`.

---

### Mistake 4: Returning the Number of Components

The answer is not the number of groups.

```text
Maximum removable = total stones - groups
```

---

### Mistake 5: Forgetting Path Compression

Correct:

```cpp
return parent[node] = findUPar(parent[node]);
```

Path compression makes repeated `find` operations very fast.

---

### Mistake 6: Using the Wrong Union Condition

If two nodes already have the same ultimate parent, they are already connected.

```cpp
if (ultimateU == ultimateV) {
    return;
}
```

Do not count an already-existing connection as a new component merge.

---

## Complexity Analysis

Let:

```text
N = number of stones
U = maxRow + maxCol + 2
```

With path compression and union by rank or size:

```text
Process all stones: O(N × α(U))
Count active components: O(N × α(U))
Extra DSU space: O(U)
Active-node map: O(N)
```

Under the usual constraints where coordinate values are `O(N)`:

```text
Time:  O(N × α(N)) ≈ O(N)
Space: O(N)
```

`α` is the inverse Ackermann function and is effectively constant for practical input sizes.

## Interview Questions

### 1. Why is the answer equal to `N - numberOfComponents`?

A connected group of `K` stones can remove exactly `K - 1` stones, leaving one stone behind.

### 2. Why use DSU instead of checking every pair of stones?

Checking every pair takes `O(N²)`. DSU performs one row-column union per stone and handles connectivity in near-linear time.

### 3. Why connect a row node to a column node?

A stone at `[row, column]` is exactly the connection between that row and column. Shared rows or columns then naturally become connected components.

### 4. Why is a column offset necessary?

Without an offset, row `0` and column `0` would be represented by the same DSU node.

### 5. Why count only active row and column nodes?

Unused DSU nodes do not represent any stone and must not be counted as components.

### 6. Can stones that do not directly share a row or column be in the same group?

Yes. They can be connected transitively through other stones.

### 7. What is the maximum number of stones that can remain?

Exactly one stone per connected group must remain.

### 8. What is the time complexity?

`O(N × α(N))`, effectively `O(N)` under standard coordinate constraints.

### 9. What is the difference between union by rank and union by size?

Both keep DSU trees shallow. Rank compares tree height estimates; size compares the number of nodes in each component.

### 10. Why is `maxRow + maxCol + 2` used for the DSU size?

The largest column node is `maxCol + maxRow + 1`, so one additional slot is needed for that index.
