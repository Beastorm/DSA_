# Print Shortest Path | Dijkstra's Algorithm

> Given a weighted undirected graph, print one shortest path from node `1` to node `N`.

The key rule is:

```text
Dijkstra finds the minimum distance.
The parent array helps us rebuild the actual path.
```

Whenever a shorter path is found:

```text
parent[adjNode] = node
```

This means:

```text
To reach adjNode in the shortest way, we came from node.
```

---

## Example 1

```text
N = 5
M = 6
Edges = [
  [1, 2, 2],
  [2, 5, 5],
  [2, 3, 4],
  [1, 4, 1],
  [4, 3, 3],
  [3, 5, 1]
]
```

The graph is weighted and undirected.

```text
1 --2-- 2
|       | \
1       4  5
|       |   \
4 --3-- 3 --1-- 5
```

We need the shortest path from:

```text
source = 1
destination = 5
```

---

## Possible Paths

### Path `1 -> 2 -> 5`

```text
1 --2-- 2 --5-- 5

Cost = 2 + 5 = 7
```

### Path `1 -> 2 -> 3 -> 5`

```text
1 --2-- 2 --4-- 3 --1-- 5

Cost = 2 + 4 + 1 = 7
```

### Path `1 -> 4 -> 3 -> 5`

```text
1 --1-- 4 --3-- 3 --1-- 5

Cost = 1 + 3 + 1 = 5
```

So the shortest path is:

```text
1 -> 4 -> 3 -> 5
```

```text
Answer = [1, 4, 3, 5]
```

---

## Why Do We Need a Parent Array?

Dijkstra normally gives the shortest distance.

```text
Shortest distance from 1 to 5 = 5
```

But this problem asks for the actual path:

```text
1 -> 4 -> 3 -> 5
```

So we store a parent for every node.

```text
parent[x] = the node from which we reached x
```

Example:

```text
parent[5] = 3
parent[3] = 4
parent[4] = 1
parent[1] = 1
```

This lets us walk backward:

```text
5 -> 3 -> 4 -> 1
```

Then reverse it:

```text
1 -> 4 -> 3 -> 5
```

---

## Initial Setup

### Distance Array

```text
dist[i] = shortest known distance from 1 to i
```

Initially:

```text
Node:  1    2    3    4    5
Dist:  0   INF  INF  INF  INF
```

Source distance is `0`:

```text
dist[1] = 0
```

---

### Parent Array

Initially every node is its own parent.

```text
Node:    1  2  3  4  5
Parent:  1  2  3  4  5
```

Why?

```text
parent[1] = 1
```

This helps us stop while rebuilding the path.

---

### Priority Queue

Dijkstra uses a min-heap.

```text
Priority Queue = [(0, 1)]
```

Each entry stores:

```text
(distance, node)
```

---

## Dijkstra Dry Run

## Step 1: Pop `(0, 1)`

Current node:

```text
node = 1
distance = 0
```

Neighbors of `1`:

```text
2 with weight 2
4 with weight 1
```

### Relax `1 -> 2`

```text
dist[1] + 2 = 0 + 2 = 2
```

`2 < INF`, so update:

```text
dist[2] = 2
parent[2] = 1
```

### Relax `1 -> 4`

```text
dist[1] + 1 = 0 + 1 = 1
```

`1 < INF`, so update:

```text
dist[4] = 1
parent[4] = 1
```

Now:

```text
Node:    1  2    3    4  5
Dist:    0  2   INF   1  INF
Parent:  1  1    3    1  5
```

Priority queue:

```text
[(1, 4), (2, 2)]
```

---

## Step 2: Pop `(1, 4)`

Current node:

```text
node = 4
distance = 1
```

Neighbors of `4`:

```text
1 with weight 1
3 with weight 3
```

### Check `4 -> 1`

```text
dist[4] + 1 = 1 + 1 = 2
```

But:

```text
dist[1] = 0
```

No update.

### Relax `4 -> 3`

```text
dist[4] + 3 = 1 + 3 = 4
```

`4 < INF`, so update:

```text
dist[3] = 4
parent[3] = 4
```

Now:

```text
Node:    1  2  3  4  5
Dist:    0  2  4  1  INF
Parent:  1  1  4  1  5
```

Priority queue:

```text
[(2, 2), (4, 3)]
```

---

## Step 3: Pop `(2, 2)`

Current node:

```text
node = 2
distance = 2
```

Neighbors of `2`:

```text
1 with weight 2
3 with weight 4
5 with weight 5
```

### Check `2 -> 1`

```text
dist[2] + 2 = 2 + 2 = 4
```

But:

```text
dist[1] = 0
```

No update.

### Check `2 -> 3`

```text
dist[2] + 4 = 2 + 4 = 6
```

But:

```text
dist[3] = 4
```

No update.

### Relax `2 -> 5`

```text
dist[2] + 5 = 2 + 5 = 7
```

`7 < INF`, so update:

```text
dist[5] = 7
parent[5] = 2
```

Now:

```text
Node:    1  2  3  4  5
Dist:    0  2  4  1  7
Parent:  1  1  4  1  2
```

Priority queue:

```text
[(4, 3), (7, 5)]
```

At this point we have a path:

```text
1 -> 2 -> 5
Cost = 7
```

But we do not stop, because a better path may still exist.

---

## Step 4: Pop `(4, 3)`

Current node:

```text
node = 3
distance = 4
```

Neighbors of `3`:

```text
2 with weight 4
4 with weight 3
5 with weight 1
```

### Check `3 -> 2`

```text
dist[3] + 4 = 4 + 4 = 8
```

But:

```text
dist[2] = 2
```

No update.

### Check `3 -> 4`

```text
dist[3] + 3 = 4 + 3 = 7
```

But:

```text
dist[4] = 1
```

No update.

### Relax `3 -> 5`

```text
dist[3] + 1 = 4 + 1 = 5
```

This is better than the old distance:

```text
dist[5] = 7
```

So update:

```text
dist[5] = 5
parent[5] = 3
```

Now:

```text
Node:    1  2  3  4  5
Dist:    0  2  4  1  5
Parent:  1  1  4  1  3
```

Priority queue:

```text
[(5, 5), (7, 5)]
```

Now the best path is:

```text
1 -> 4 -> 3 -> 5
Cost = 5
```

---

## Step 5: Pop `(5, 5)`

Current node:

```text
node = 5
distance = 5
```

Final shortest distance:

```text
dist[5] = 5
```

Final parent array:

```text
Node:    1  2  3  4  5
Parent:  1  1  4  1  3
```

---

## Path Reconstruction

Start from destination `5`.

```text
node = 5
```

Follow the parent array:

```text
parent[5] = 3
parent[3] = 4
parent[4] = 1
parent[1] = 1
```

Backward path:

```text
5 -> 3 -> 4 -> 1
```

Reverse it:

```text
1 -> 4 -> 3 -> 5
```

```text
Answer = [1, 4, 3, 5]
```

---

## Why Start Backtracking from `N`? 💡

The parent array stores where each node came from.

```text
parent[5] = 3
```

This means:

```text
To reach 5, we came from 3.
```

So we must start from the destination and move backward.

```text
5 -> 3 -> 4 -> 1
```

Then reverse the result.

---

## Why `parent[i] = i` Initially?

At the start:

```text
parent[i] = i
```

For the source:

```text
parent[1] = 1
```

During path reconstruction, we stop when:

```text
parent[node] == node
```

This tells us:

```text
We reached the source node.
```

---

## Why Not Stop When We First Reach Destination?

When node `5` first gets distance `7`, the path is:

```text
1 -> 2 -> 5
```

But later, we find a better path:

```text
1 -> 4 -> 3 -> 5
```

with cost:

```text
5
```

So in Dijkstra, we continue processing according to the min-heap.

---

## Algorithm

```text
1. Create a weighted adjacency list.

2. Initialize distance array:
      dist[1] = 0
      all other distances = infinity

3. Initialize parent array:
      parent[i] = i

4. Push source into min-heap:
      (0, 1)

5. Run Dijkstra:
      while priority queue is not empty:
          a. Pop the node with minimum distance.
          b. Traverse all its neighbors.
          c. If a shorter path is found:
                update distance
                update parent
                push new distance into priority queue

6. If dist[N] is infinity:
      return [-1]

7. Otherwise, reconstruct the path:
      start from N
      follow parent[node]
      stop when parent[node] == node

8. Reverse the path and return it.
```

---

## Dijkstra Relaxation

The main condition is:

```text
if dist[node] + edgeWeight < dist[adjNode]
```

It asks:

```text
Is going to adjNode through node shorter than the old known path?
```

If yes:

```text
dist[adjNode] = dist[node] + edgeWeight
parent[adjNode] = node
```

Example:

```text
Old dist[5] = 7
New dist[5] = dist[3] + 1 = 4 + 1 = 5
```

Since `5 < 7`:

```text
dist[5] = 5
parent[5] = 3
```

## C++ Code — Complete Program

```cpp
#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    vector<int> shortestPath(int n, int m, vector<vector<int>>& edges) {
        vector<vector<pair<int, int>>> adj(n + 1);

        // Build the undirected weighted graph.
        for (auto& edge : edges) {
            int u = edge[0];
            int v = edge[1];
            int wt = edge[2];

            adj[u].push_back({v, wt});
            adj[v].push_back({u, wt});
        }

        priority_queue<
            pair<int, int>,
            vector<pair<int, int>>,
            greater<pair<int, int>>
        > pq;

        vector<int> dist(n + 1, 1e9);
        vector<int> parent(n + 1);

        for (int i = 1; i <= n; i++) {
            parent[i] = i;
        }

        dist[1] = 0;
        pq.push({0, 1});

        while (!pq.empty()) {
            int dis = pq.top().first;
            int node = pq.top().second;
            pq.pop();

            for (auto it : adj[node]) {
                int adjNode = it.first;
                int edgeWeight = it.second;

                if (dis + edgeWeight < dist[adjNode]) {
                    dist[adjNode] = dis + edgeWeight;
                    pq.push({dist[adjNode], adjNode});
                    parent[adjNode] = node;
                }
            }
        }

        if (dist[n] == 1e9) {
            return {-1};
        }

        vector<int> path;
        int node = n;

        while (parent[node] != node) {
            path.push_back(node);
            node = parent[node];
        }

        path.push_back(1);
        reverse(path.begin(), path.end());

        return path;
    }
};

int main() {
    Solution solution;

    int n = 5;
    int m = 6;

    vector<vector<int>> edges = {
        {1, 2, 2},
        {2, 5, 5},
        {2, 3, 4},
        {1, 4, 1},
        {4, 3, 3},
        {3, 5, 1}
    };

    vector<int> answer = solution.shortestPath(n, m, edges);

    cout << "Shortest path: ";
    for (int node : answer) {
        cout << node << " ";
    }
    cout << endl;

    return 0;
}
```

**Output:**

```text
Shortest path: 1 4 3 5
```

## Slightly Safer Version

Sometimes the same node can enter the priority queue multiple times.

Example:

```text
(7, 5)
(5, 5)
```

`(7, 5)` becomes an old entry after we find distance `5`.

To ignore old entries, add this after popping:

```cpp
if (dis != dist[node]) {
    continue;
}
```

So the loop becomes:

```cpp
while (!pq.empty()) {
    int dis = pq.top().first;
    int node = pq.top().second;
    pq.pop();

    if (dis != dist[node]) {
        continue;
    }

    for (auto it : adj[node]) {
        int adjNode = it.first;
        int edgeWeight = it.second;

        if (dis + edgeWeight < dist[adjNode]) {
            dist[adjNode] = dis + edgeWeight;
            pq.push({dist[adjNode], adjNode});
            parent[adjNode] = node;
        }
    }
}
```

## Why BFS Is Not Used Here

BFS works when all edges have equal weight.

Here weights are different:

```text
1 -> 2 has weight 2
1 -> 4 has weight 1
2 -> 5 has weight 5
3 -> 5 has weight 1
```

BFS counts only the number of edges.

Dijkstra counts the total path cost.

So for weighted graphs with non-negative weights:

```text
Use Dijkstra's Algorithm.
```

## If No Path Exists

Suppose node `N` cannot be reached from node `1`.

Then:

```text
dist[N] = infinity
```

So return:

```text
[-1]
```

Example:

```text
N = 5
Edges = [
  [1, 2, 2],
  [2, 3, 4]
]
```

Node `5` is unreachable.

```text
Answer = [-1]
```

---

## Multiple Shortest Paths

There can be more than one shortest path.

Example:

```text
1 -> 2 -> 5 = 7
1 -> 3 -> 5 = 7
```

Both are valid.

Dijkstra may return any one of them depending on the order of processing.

---

## Edge Cases

### Destination Unreachable

```text
There is no path from 1 to N.
```

```text
Return [-1]
```

### Only One Node

```text
N = 1
```

Source and destination are the same.

```text
Return [1]
```

### Multiple Shortest Paths

```text
Two or more paths have the same minimum cost.
```

```text
Return any one valid shortest path.
```

### Directed Graph

For an undirected graph, add both edges:

```text
u -> v
v -> u
```

For a directed graph, add only one edge:

```text
u -> v
```

### Negative Weights

Dijkstra does not work correctly with negative edge weights.

```text
Use Bellman-Ford instead.
```

---

## Complexity

Let:

```text
N = number of nodes
M = number of edges
```

| Resource | Complexity |
|---|---:|
| Build adjacency list | `O(M)` |
| Dijkstra using priority queue | `O(M log N)` |
| Path reconstruction | `O(N)` |
| Extra space | `O(N + M)` |

Total time:

```text
O(M log N + N)
```

Usually written as:

```text
O(M log N)
```

## Interview Questions

### 1. What extra array is used to print the shortest path?
The `parent` array.

### 2. What does `parent[x]` store?
It stores the previous node used to reach `x` in the shortest path.

### 3. When do we update `parent[adjNode]`?
Only when we find a shorter path to `adjNode`.

### 4. Why do we initialize `parent[i] = i`?
So that the source node points to itself, which helps us stop during backtracking.

### 5. Why do we reconstruct the path from `N` to `1`?
Because each node knows its parent, so we can move backward from destination to source.

### 6. Why do we reverse the path at the end?
Because backtracking gives the path in reverse order.

### 7. What if `dist[N]` remains infinity?
It means node `N` is unreachable, so return `[-1]`.

### 8. Why not use BFS for this problem?
Because the graph has different edge weights. BFS does not consider weights.

### 9. Can Dijkstra work with negative weights?
No. Use Bellman-Ford for negative weights.

### 10. What is the time complexity?
`O(M log N)` using a priority queue.
