## 1. Problem Statement

Given an **undirected, unweighted graph** with `N` vertices and `M` edges, find the **shortest distance from source node `src` to ALL other vertices**. All edges have a weight of `1`.

**Input Format:**

- `N` = number of vertices
- `M` = number of edges
- `src` = source vertex (given as `0`)
- Edge list `(u, v)` for each undirected edge

**Output:**

- Array of shortest distances from source to all vertices
- `-1` for unreachable vertices

## Key Insight

```
  All edges have UNIT WEIGHT = 1.

  Why BFS works perfectly here?

  BFS explores nodes LEVEL BY LEVEL:

  Level 0: source (dist=0)
  Level 1: all nodes 1 hop away (dist=1)
  Level 2: all nodes 2 hops away (dist=2)
  ...

  First time BFS reaches a node = SHORTEST path!

  (No need for Dijkstra's min-heap with unit weights)

  Weighted graph (different weights) → Dijkstra
  Unit weight graph                  → BFS ✓
```

---

## Intuition

```
  Imagine dropping a stone in a still pond:

  1. The ripple starts exactly at the source.
  2. It expands outward one ring at a time.
  3. Every point the ripple touches first is via the shortest route.

  BFS is exactly that ripple:

  - Queue holds the current wavefront.
  - We process the entire wavefront (level) before moving to the next.
  - Since every edge is 1 unit long, each new wave is exactly 1 unit farther.

  Why it works:
  When a node is first visited, we have already reached it through the
  minimum number of edges possible. No later path can be shorter because
  every path to it must contain at least that many edges.
```

## Algorithm

```
  shortestPathUnitWeight(N, edges, src):

  1. Build adjacency list from edges (undirected)

  2. Initialize dist[] = infinity for all nodes
     dist[src] = 0

  3. BFS from src:
       Push src to queue
       While queue not empty:
           node = queue.front(); pop
           For each neighbor of node:
               If dist[node] + 1 < dist[neighbor]:
                   dist[neighbor] = dist[node] + 1
                   push neighbor to queue

  4. Build result:
       If dist[i] != infinity → ans[i] = dist[i]
       Else                   → ans[i] = -1 (unreachable)

  5. Return ans
```

```
  Why check dist[node]+1 < dist[neighbor]?

  Ensures we only update if a shorter path is found.
  For unit weight undirected graph + BFS:
  Each node is processed only ONCE in practice
  (first visit = shortest path for unit weights).
```

## Code

```cpp
#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    vector<int> shortestPath(vector<vector<int>>& edges, int N, int M, int src) {
        // Step 1: Build undirected adjacency list
        vector<vector<int>> adj(N);
        for (auto& edge : edges) {
            adj[edge[0]].push_back(edge[1]);
            adj[edge[1]].push_back(edge[0]); // Undirected
        }

        // Step 2: Initialize distances to infinity
        vector<int> dist(N, 1e9);
        dist[src] = 0;

        // Step 3: BFS from source
        queue<int> q;
        q.push(src);

        while (!q.empty()) {
            int node = q.front();
            q.pop();

            for (int neighbor : adj[node]) {
                // Found shorter path to neighbor
                if (dist[node] + 1 < dist[neighbor]) {
                    dist[neighbor] = dist[node] + 1;
                    q.push(neighbor);
                }
            }
        }

        // Step 4: Build result (-1 for unreachable)
        vector<int> ans(N, -1);
        for (int i = 0; i < N; i++) {
            if (dist[i] != 1e9) {
                ans[i] = dist[i];
            }
        }

        return ans;
    }
};

int main() {
    int N = 9, M = 10;
    vector<vector<int>> edges = {
        {0,1},{0,3},{3,4},{4,5},
        {5,6},{1,2},{2,6},{6,7},
        {7,8},{6,8}
    };

    Solution obj;
    vector<int> ans = obj.shortestPath(edges, N, M, 0);

    cout << "Shortest distances from node 0: ";
    for (int x : ans) cout << x << " ";
    cout << endl;

    return 0;
}
```

## Edge Cases

```
  Source is isolated:
  src=0, adj[0]=[]
  dist[0]=0, rest = -1 ✓

  Disconnected graph:
  0 ─── 1 ─── 2      3 ─── 4  (separate component)

  BFS from 0 never reaches 3, 4.
  dist[3]=∞, dist[4]=∞
  Final result:
  ans[3] = -1 (unreachable)
  ans[4] = -1 (unreachable) ✓

  Single node:
  N=1, no edges
  ans=[0] ✓

  Linear chain 0─1─2─3─4:
  dist=[0,1,2,3,4] ✓

  All nodes connected:
  dist[] all updated ≠ ∞
  No -1 in result ✓
```

## Complexity Analysis

**Time Complexity:** O(N + M)

- Building adjacency list: O(M)
- BFS traversal: O(N + 2M) ← each node once, each edge twice (undirected)
- Building result: O(N)
- Total: **O(N + M)**

**Space Complexity:** O(N + M)

- Adjacency list: O(N + 2M)
- Distance array: O(N)
- BFS queue: O(N)
- Result array: O(N)
- Total: **O(N + M)**

```
  N = vertices, M = edges

  BFS = optimal for unit weight shortest path
  No priority queue needed! ✓
  Simpler and faster than Dijkstra for this case ✓

  Comparison with other shortest path algorithms:

  | Algorithm        | Graph Type           | Time Complexity      |
  |------------------|----------------------|----------------------|
  | BFS              | Unit weight          | O(N + M)             |
  | Dijkstra         | Non-negative weights | O((N+M) log N)       |
  | Bellman-Ford     | Any weights          | O(N × M)             |
```

## Interview Questions

```
 Q1: Why does BFS work for finding shortest paths in unweighted graphs?

A: Think of dropping a stone in a pond. The ripples spread outward in circles:

Circle 1 = places 1 step away
Circle 2 = places 2 steps away
Circle 3 = places 3 steps away

BFS works the same way. It checks all nearby spots first, then moves one step further out. Because it explores layer by layer, the very first time it reaches a place, it took the fewest steps possible to get there.

------------------------------------------------------------

Q2: Why can't we use BFS for weighted graphs with different edge weights?

A: BFS only counts the number of roads, not how long the roads are.

Imagine two options to reach a store:

Option A: 1 road, but it is 10 miles long.
Option B: 2 roads, but each is only 1 mile long (total = 2 miles).

BFS would wrongly pick Option A because it is only 1 road. For roads with different lengths, you need Dijkstra's algorithm.

------------------------------------------------------------

Q3: Why is Dijkstra not needed for unit weight graphs?

A: When every road is the exact same length (1 mile), counting roads is the same thing as counting miles.

BFS uses a simple waiting line (a queue) that naturally processes the closest places first. Dijkstra uses a more complex sorting tool (a min-heap) which does unnecessary extra work when all roads are equal.

------------------------------------------------------------

Q4: What does the condition dist[node] + 1 < dist[neighbor] do?

A: In simple words, it asks:
"Is going through the current spot shorter than the best route we found so far?"

If YES: Update the distance and put the neighbor in line to be checked.
If NO: Ignore it, because we already have a faster way there.

------------------------------------------------------------

Q5: Can a node be enqueued multiple times in this BFS?

A: In practice, no.

Because BFS moves outward evenly, the first time you visit a place is always the shortest way. Any future visits to that same place will be equal or longer, so the check in Q4 will be false and won't add it again.

------------------------------------------------------------

Q6: How do you handle unreachable nodes?

A:

At the start, set every place's distance to a huge number (like 1 billion) to mean "unreachable."
Run your BFS.
At the end, check every place. If a place still has a distance of 1 billion, it means you could never reach it. Change its distance to -1.

------------------------------------------------------------

Q7: What is the difference between BFS and DFS for shortest path?

A:

BFS (Breadth-First Search):

Explores layer by layer (like water ripples).
Always finds the shortest path when all steps are equal.
Best for finding the shortest path or nearest item.

DFS (Depth-First Search):

Dives straight down one path until it hits a dead end, then backs up.
Does NOT guarantee the shortest path.
Best for exploring every path, finding mazes, or detecting loops.

------------------------------------------------------------

Q8: Why use 1e9 as infinity instead of INT_MAX?

A: To prevent computer math errors (overflow).

If a distance is set to the absolute maximum number a computer can hold (INT_MAX), and your code tries to add 1 to it (dist + 1), the number rolls over into a negative number and breaks your program. Using 1 billion (1e9) is huge enough to mean "infinity" but safe to add numbers to.

------------------------------------------------------------

Q9: Can this algorithm work on directed graphs (one-way roads)?

A: Yes! The BFS logic stays exactly the same.

The only difference is how you set up the map:

Two-way roads: Connect point A to B, and B to A.
One-way roads: Connect point A to B only.

------------------------------------------------------------

Q10: How would you find the actual shortest path, not just the distance?

A: Leave a trail of breadcrumbs.

Every time you step into a new place, write down where you just came from:

"I got to Place 2 from Place 1"
"I got to Place 1 from Place 0"

When you reach the end, just follow the trail backward to see the exact route: 0 -> 1 -> 2.

------------------------------------------------------------

Q11: What if the source is not node 0?

A: It works for any starting point.

Just set your chosen starting place's distance to 0, put it in the queue first, and run the exact same BFS.

------------------------------------------------------------

Q12: When should you prefer Dijkstra over BFS?

A:

Use BFS when all roads/steps have the exact same cost (usually 1). It is faster and simpler.
Use Dijkstra when roads have different lengths, costs, or times.

------------------------------------------------------------

Q13: How does multi-source BFS work?

A: Imagine dropping 3 stones in a pond at the exact same moment.

Instead of starting with 1 place in your line, you put all starting places into the line at distance 0.

BFS expands from all of them at once. This lets you quickly find which starting point is closest to every other spot on the map (like finding the nearest hospital or fire station).

------------------------------------------------------------

Q14: What are common bugs in BFS shortest path implementations?

A:

Forgetting two-way roads: Adding the connection in only one direction.
Forgetting the start: Not setting the starting place's distance to 0.
Infinite loops: Forgetting to check if a place was already visited.
Output errors: Returning 1 billion instead of -1 for unreachable places.
Index mix-ups: Confusing 0-based counting (0, 1, 2) with 1-based counting (1, 2, 3).

------------------------------------------------------------

Q15: Is BFS greedy? Why or why not?

A: Not really.

A "greedy" algorithm constantly searches and picks the single best choice at every moment (like Dijkstra).

BFS doesn't pick favorites. It simply checks every neighbor at distance 1, then every neighbor at distance 2, and so on. Because all steps are equal, this simple layer-by-layer check naturally arrives at the shortest path.
```
